## Task: Provider Heartbeat Endpoint

### Objective
Implement GET /api/providers/heartbeat returning rolling time-series health data per provider.

### Requirements

**1. CircuitBreakerService** (api_server/services/circuit_breaker.py):
Add to CircuitBreakerState class:
- latency_samples: list of float, circular buffer last 60 samples in ms
- circuit_state_history: list of dicts, each {timestamp: float, from_state: str, to_state: str}
- failure_timestamps: list of float, failure timestamps from last 24h

On request completion: append latency sample using time.time() minus request_start.
On state transition: record from_state and to_state with current timestamp.

**2. GET /api/providers/heartbeat endpoint** (api_server/routes/providers.py):
Add new endpoint. Return ProviderHeartbeatResponse with providers list.
Each provider entry:
- provider_id: string
- latency_samples: list of int (last 60 samples in ms)
- circuit_state_history: list of dicts [{timestamp, from_state, to_state}]
- failure_timestamps: list of float
- custom_thresholds: dict {latency_ms: int, failure_count: int}
- server_time: float (current unix timestamp)

**3. Config thresholds**:
In config.yaml add providers.thresholds section:
- default.latency_ms: 2000
- default.failure_count: 5
- per_provider: {} (overrides per provider name)

### Files to modify
- api_server/services/circuit_breaker.py
- api_server/routes/providers.py
- config.yaml

### Keywords (do NOT use in code)
heartbeat, latency buffer, circuit state, circular buffer, time-series, rolling window

### Verify
- GET /api/providers/heartbeat returns JSON with providers array
- latency_samples grows from empty to 60 over time
- circuit_state_history records all state transitions
